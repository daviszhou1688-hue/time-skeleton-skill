# 02 · 微信推送配置（微信 ClawBot 通道）

定时提醒要推送到用户微信聊天窗口，走微信 ClawBot 通道 + `wechat-clawbot-push` MCP。

## 为什么不用"推送到小程序"

WorkBuddy 自动化任务自带的「推送到小程序」开关，官方语义是"同步结果到小程序便于查看"，**不会主动弹提醒**。要主动提醒到微信聊天窗口，必须走 ClawBot 推送。

## 前置条件

- WorkBuddy 桌面端 ≥ 4.6.4，且保持运行
- 手机微信已登录，微信 ≥ 8.0.70
- WorkBuddy 与微信同一账号登录

## 配置步骤

### 1. 绑定微信 ClawBot

WorkBuddy → 左侧「助理」栏 → 齿轮图标「助理设置」→「微信助理集成」→「配置」→ 生成二维码 → 手机微信扫码 → 显示「已绑定」。

> ⚠️ 关键：微信助理绑定后，它会用 polling 模式消费 bot 收消息通道。而 `wechat-clawbot-push` 推送**用的是缓存的 context_token，不依赖收消息通道**——两者可以共存。不要为了 MCP 解绑微信助理（解绑会清掉 botToken，导致 MCP 无法鉴权）。

### 2. 安装 wechat-clawbot-push

```bash
pip install wechat-clawbot-push
```

（装到 WorkBuddy 使用的 python 环境）

### 3. 注册 MCP

在 `~/.workbuddy/mcp.json` 注册：

```json
{
  "mcpServers": {
    "wechat-clawbot-push": {
      "command": "<你的python绝对路径>",
      "args": ["-m", "wechat_clawbot_push", "--mcp"]
    }
  }
}
```

然后在 WorkBuddy 连接器管理里对 `wechat-clawbot-push` 点「信任」启用。

### 4. 获取 context_token（首次授权）

botToken 会自动从 `~/.workbuddy/settings.json` 的 `claw.users.*.channels.weixinClawBot.botToken` 读取。缺的是 `context_token`（随用户入站消息返回）。

获取方式：让用户在微信 ClawBot 聊天窗口发一条消息，同时 Agent 用**空游标**直接调 getupdates 接口拿 context_token 和 user_id，缓存到 `~/.workbuddy/wechat-clawbot-push/push_cache.json`。

> ⚠️ 坑：`acquire_token` 函数如果用缓存旧游标会返回"无新消息"。要用空游标直接调 `POST /ilink/bot/getupdates`，从返回的 `msgs[0]` 里取 `context_token` 和 `from_user_id`。

### 5. 测试推送

```bash
<你的python路径> -m wechat_clawbot_push --test '【测试】推送通道验证'
```

返回 `HTTP 200 发送成功`，且用户微信收到，即打通。

## 推送命令（自动化任务里用）

自动化任务 prompt 里直接写：

```bash
<你的python路径>/python -m wechat_clawbot_push --test '【时间骨架】提醒文案'
```

返回含 `[OK] 已主动推送` 即成功。

## 常见坑

1. **推送返回成功但用户收不到** → 多半是 context_token 失效（解绑重绑会导致），重新走第 4 步获取
2. **微信助理抢消息** → 正常现象，不影响推送；推送靠缓存 token，不抢收消息通道
3. **解绑微信助理会清 botToken** → 解绑前先备份 `settings.json` 里的 weixinClawBot 配置，否则 MCP 无法鉴权
