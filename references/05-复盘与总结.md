# 05 · 复盘与总结

打卡系统不能停在"记录"，要形成"记录 → 复盘 → 建议 → 调整"的闭环。这一层是周复盘 + 月总结。

## 核心理念

复盘不是算分，是产出**可执行的下一步动作**。建议要"三合一"：
1. **近期情况**：结合打卡数据（一句话、未执行原因）分析真实状态
2. **外部权威**：现场检索权威大师（如 Huberman 睡眠法、James Clear《原子习惯》）+ GitHub 优质项目，给可落地的建议
3. **知识库实际**：读用户已沉淀的原则，过滤掉与其三观冲突的建议

合并成具体动作，数量克制（周 2-3 条，月 1-2 条），每条能落地、可检验。

## 配置步骤

### 1. 写复盘 SOP 到知识库

按用户指定的知识库位置，写一份 `复盘与总结SOP.md`，内容包含：
- 周复盘步骤（查库 → 算达标率 → 生成周文档 → 三合一建议）
- 月总结步骤（同，取 30 天，更宏观）
- 周/月文档模板
- 三合一建议的执行要点
- 防错规则

### 2. 建周复盘定时任务

- rrule: `FREQ=WEEKLY;BYDAY=SU;BYHOUR=15;BYMINUTE=0`（周日下午 15:00）
- prompt 指向复盘 SOP，执行：查近 7 天 → 算达标率/起床趋势/精力均值 → 生成周文档 → 三合一建议

### 3. 建月总结定时任务

- 每月最后一天 15:00
- ⚠️ rrule 坑：WorkBuddy 的 automation 不支持 `BYMONTHDAY=-1`（月末）语法。改用：
  - rrule: `FREQ=DAILY;BYMONTHDAY=28,29,30,31;BYHOUR=15;BYMINUTE=0`（每月 28-31 号都触发）
  - prompt 里先判断"今天是否本月最后一天"（用 `date` 取今天，对比明天是否跨月），不是最后一天直接结束，是才执行月总结

## 周文档模板

```markdown
# 2026-W{周号} 时间骨架周报

> 复盘周期：{周一日期}（周一）～ {周日日期}（周日）

## 一、本周数据回顾

| 项目 | 达标率 | 达标天数 |
|------|--------|----------|
| 就寝 | X% | X/7 |
| 起床 | X% | X/7 |

- 起床时间趋势：平均 X:XX，目标 ≤7:20，超红线 X 天
- 精力均值：X.X / 5
- 滚动 14 天达标率：X%

## 二、每日记录

### {日期} 周一
就寝{状态}{原因} · 起床{状态}{原因} · 精力 X
一句话：...

## 三、近期情况分析
## 四、外部优化建议
## 五、结合知识库实际情况
## 六、下周可执行动作
1. ...
```

> ⚠️ 每日记录里，❌ 的项目必须带当时写的「未执行原因」，没写的标"原因未填"。

## 月总结文档模板

```markdown
# 2026-{M月} 时间骨架月度总结

## 一、月度整体达标率
## 二、本月 vs 上月对比
## 三、本月关键事件与原因
## 四、外部优化建议
## 五、结合知识库
## 六、下月核心调整方向（1-2 条）
```

## 防错规则

- 周号用 ISO 周（周一开始）
- 数据以数据库为准，不臆造
- 未达标原因从「未执行原因」字段取，没有就写"原因未填"
- 检索不到强相关建议时，如实写"本周未检索到强相关建议"，不硬凑
- 月总结任务必须先判断是否真月末，避免 28-31 号重复生成
