# 01 · 搭建步骤

搭建「时间骨架」系统的完整分步流程。执行时严格按顺序，每步完成后再进下一步。

---

## 第 1 步：创建资料库数据库

用资料库 skill 的建库脚本创建一个 database，作为打卡数据的唯一数据源。

**默认骨架项（2 项）**，字段如下：

| 字段名 | 类型 | 说明 |
|---|---|---|
| 日期 | date | 打卡日期（YYYY-MM-DD） |
| 就寝 | select | 三态：✅达标 / 🟡弹性卡 / ❌未执行 |
| 就寝备注 | text | 实际关灯时间，如 `23:40`（可选） |
| 起床 | select | 三态 |
| 起床备注 | text | 实际离床时间，如 `7:10`（可选） |
| 未执行原因 | text | ❌ 项目必须写原因 |
| 精力 | number | 1–5 自评（可选） |
| 一句话 | text | 当天一句话（可选） |

**建库方式**：用资料库 skill 的 `create_database.py`，或直接调用 `space.database.create-database` API。记录返回的 **database_id**（后续所有步骤用这个 ID）。

---

## 第 2 步：生成并发布看板页

1. 取 `assets/kanban-template.html`
2. 把里面所有 `<资料库ID>` 占位符替换成第 1 步拿到的真实 database_id
3. 检查无第三方图片外链后，用资料库 skill 的 `import_html.py` 发布为资料库 page
4. 记录返回的看板链接（给用户看）

看板是**纯观测展示**，不含打卡表单。打卡通过微信回复，Agent 登记后看板自动刷新。

---

## 第 3 步：配置定时提醒任务

用 `automation_update` 工具创建提醒任务。**默认两个**：

### 就寝提醒（每天 23:30）

- rrule: `FREQ=DAILY;BYHOUR=23;BYMINUTE=30`
- prompt 核心：用 Bash 调用微信推送命令（见 `02-微信推送配置.md`），文案示例：
  `【时间骨架】就寝提醒：23:30 了，准备就寝（≤24:00 关灯+放下手机）。完成后回复打卡。`

### 起床提醒（每天 8:30）

- rrule: `FREQ=DAILY;BYHOUR=8;BYMINUTE=30`
- prompt 核心：同样调微信推送命令，文案示例：
  `【时间骨架】起床提醒：8:30 了，起床打卡（离床时间）。完成后回复打卡。`

**推送命令模板**（替换文案即可）：

```bash
<你的python路径>/python -m wechat_clawbot_push --test '【时间骨架】XXX提醒文案'
```

**可选增强**（用户需要时再加）：
- 就寝补提醒 00:30（prompt 里先查数据库当日「就寝」是否已打卡，未打卡才推）
- 其他项目提醒（参考 `04-扩展项目指南.md`）

---

## 第 4 步：配置微信推送通道

见 `02-微信推送配置.md`。核心：安装 `wechat-clawbot-push` MCP + 绑定微信 ClawBot + 获取 context_token。完成后测试推送一条，确认用户微信能收到。

---

## 第 5 步：写打卡登记交接文档

见 `03-打卡登记闭环.md`。生成一份交接文档，让微信 ClawBot 读后能解析用户打卡回复、写入数据库。

---

## 验收清单（全部通过才算搭好）

- [ ] 数据库已建，含就寝/起床字段，拿到了 database_id
- [ ] 看板页已发布，能正常显示（打开链接能看到空看板）
- [ ] 起床/就寝提醒任务已建，到点能自动推送
- [ ] 微信推送测试通过（用户收到测试消息）
- [ ] 交接文档已写，微信 ClawBot 读了能登记打卡
